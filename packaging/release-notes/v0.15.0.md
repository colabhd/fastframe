fastframe 0.15.0 opens an app's window on computers without a graphics driver, and explains itself when it cannot. eframe's glow renderer needs OpenGL 2, and a Windows PC without its graphics driver (the Microsoft Basic Display Adapter, many virtual machines, some Remote Desktop sessions) has only OpenGL 1.1, so every fastframe app quit there without a word. The new `fastframe-graphics` crate falls back to wgpu, which draws through Direct3D 12 and Windows' own software renderer, and shows a native dialog with a link to the app's help page when no renderer can draw.

Upgrade by moving every fastframe crate to the tag, and add `fastframe-graphics`:

```toml
fastframe-graphics = { git = "https://github.com/crmne/fastframe", tag = "v0.15.0" }
```

Nothing changes for an app that does not adopt it. [MIGRATION.md](https://github.com/crmne/fastframe/blob/v0.15.0/MIGRATION.md#fastframe-graphics) has the steps.

## New

- **Windows open without OpenGL 2 (`fastframe-graphics`, `Graphics::run_native`).** `Graphics::new(name).help(url).run_native(options, app_creator)` replaces `eframe::run_native`. It opens the window with glow; when glow cannot draw it and the app turned on the crate's `wgpu` feature, it opens it again with wgpu. On a Windows 11 virtual machine with only the Microsoft Basic Display Adapter, glow failed with `egui_glow requires opengl 2.0+` and wgpu drew the window with Direct3D 12 on the Microsoft Basic Render Driver. The feature adds about 7 MB to a Windows release binary, so each app chooses it, for example only under `cfg(windows)`. Another renderer is tried only while the window has not started, so an app's own errors and panics are never retried. Later windows use the renderer that worked, and `renderer()` names it for error reports. By @crmne; thanks to the Solco first-run test on Windows, which found Solco quitting silently on that virtual machine.

  ![The fallback window, drawn with wgpu on the Microsoft Basic Display Adapter](https://github.com/crmne/fastframe/releases/download/v0.15.0/graphics-wgpu-fallback-windows.png)

- **A native dialog says why no window opened (`Graphics::explain`).** When no renderer can draw, the app shows its name, the cause, what to install, the error's details, and offers its help page: a message box on Windows, an alert on macOS, and zenity or kdialog on Linux. An app started from Explorer has no console, so this is the only place the error was ever visible. By @crmne.

  ![The dialog on Windows, offering the app's help page](https://github.com/crmne/fastframe/releases/download/v0.15.0/graphics-dialog-windows.png)

- **A fastframe-shell `Lease` can be cloned**, so an app creator that `run_native` makes twice can take the app in whichever try starts. Only one take succeeds. By @crmne.

## Known limitations

- **WARP draws on the processor.** An app falls back to it only without a driver, and runs there slowly rather than not at all.
- **wgpu cannot draw in a Windows session without a desktop**, such as a program started over SSH. It panics configuring the window; `run_native` catches that panic before the window starts and shows the dialog, but an app's panic hook sees it first.
- **The macOS and Linux dialogs were compiled and unit-tested, not seen on screen.** Every supported Mac has OpenGL; on Linux the dialog needs zenity or kdialog, and without either the error goes to the log only.
