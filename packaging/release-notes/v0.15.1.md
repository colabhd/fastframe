fastframe 0.15.1 lets an app put the missing-graphics dialog in its own words, and points Windows on ARM to the right fix. Snapdragon graphics drivers have no OpenGL, so on those PCs the dialog now offers Microsoft's OpenCL, OpenGL & Vulkan Compatibility Pack instead of telling people to install a driver that would not help.

Upgrade by moving every fastframe crate to the tag. Nothing changes in an app's code:

```toml
fastframe-graphics = { git = "https://github.com/crmne/fastframe", tag = "v0.15.1" }
```

## New

- **The dialog in the app's words (`Graphics::dialog`, `Dialog`, `Trouble`, `Cause`).** An app passes a closure that gets the app's name, the cause, the error's details and its help page, and returns the dialog's title, body, link and button labels, for example in the person's language. It can start from `Dialog::english(trouble)` and change only the words. By @crmne, upstreamed from Spotifast's own dialog, which is translated into its 16 languages.

## Fixed

- **Windows on ARM is told to install the compatibility pack (`Cause::WindowsOnArm`, `COMPATIBILITY_PACK_PAGE`).** Windows on ARM gets OpenGL from Microsoft's OpenCL, OpenGL & Vulkan Compatibility Pack, a Store app that translates it to Direct3D 12, so there the dialog explains that and its button opens the pack's Microsoft Store page. Windows is asked for its processor at run time, so an x64 build running emulated on ARM gets the same remedy. By @crmne, from Spotifast's dialog.

## Known limitations

- **The Windows on ARM path was not run on an ARM PC.** The detection uses `IsWow64Process2` and was compiled and unit-tested; no ARM machine was available.
- The limitations in [0.15.0](https://github.com/crmne/fastframe/releases/tag/v0.15.0) still apply.
