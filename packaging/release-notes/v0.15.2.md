fastframe 0.15.2 lets an app test its own words for the missing-graphics dialog. `Trouble` gained a constructor, so a test can build the trouble the dialog hook receives for each cause.

Upgrade by moving every fastframe crate to the tag. Nothing changes in an app's code:

```toml
fastframe-graphics = { git = "https://github.com/crmne/fastframe", tag = "v0.15.2" }
```

## New

- **`Trouble::new(app_name, cause, details, help_url)`.** `Trouble` and `Cause` stay `#[non_exhaustive]`, so later fields and causes arrive without breaking an app, which left no way to make one outside fastframe. Keep the words in a function, pass it to `Graphics::dialog`, and call it in a test with `Trouble::new` for each `Cause`; the method's documentation has an example. By @crmne; thanks to the Spotifast session, which found it while adopting 0.15.1.
